  - `scripts/fingerprint.js`：取设备指纹。先看有没有存过（localStorage / IndexedDB 两处都存），没有才算一次；算的时候用 FingerprintJS，算不出来还有一套兜底哈希（画布 + 屏幕 + 时区 + 语言）。清掉其中一处存储能从另一处恢复；两处都清掉，FingerprintJS 算出来还是同一个。
  - `scripts/risk.js`：注册成功后往 `signup_risk` 表登记一条（指纹、用户名、用户 id、时间；IP 由服务端从请求头取，客户端填不了），并让服务端判一次是不是高风险。
  - `supabase/risk.sql`：风控表、行级安全策略、判定函数，以及把高风险账号的收藏/偏好写入策略收紧。真正的拦截在数据库里，前端只是提示一句——改前端绕不过去。
- 软限制：同一台设备 24 小时内注册超过 2 个账号，账号照样注册成功、照样能登录看作品，但收藏和偏好同步被停用。IP 的阈值放宽到 5（IP 只能粗略到"一个出口"，国内移动网络是 CGNAT，咖啡厅和写字楼背后是很多真人共用一个出口，压到 2 会误伤正常用户）。
- 设置面板里，高风险账号会显示一行提示，说明为什么同步没生效。

  - 预览用的三帧 iframe 里，只有后加载的两帧设了 `pointer-events:none`，最初那帧（星球版）没有；它透明之后仍然在栈底把点击和滚轮全吃了，于是看不见的帧在挡、看得见的帧反而点不动。现在指针事件跟着「正在显示的那一帧」走。
